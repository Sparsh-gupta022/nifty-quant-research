| 3.1 | Significant fall | A: fixed ≤ −2% · B: volatility-scaled · C: both | B — close-to-close return < −2 × std of previous 60 trading days' returns (t−60…t−1, no look-ahead). | 3.2 | Recovery definition | A: forward return > 0 · B: forward return > baseline · C: regains event-day loss · plus: main test = retracement (X) vs forward return (Y); daily High vs Close | **Main: 50% retracement using daily Close.** loss = prev-day Close − event-day Close; recovery_level = event-day Close + 0.5 × loss; recovered if any daily Close within the holding period ≥ recovery_level (20,000 → 19,000 ⇒ level 19,500). **Baseline:** same measurement on non-event days (days not meeting the 2× vol fall rule); compare event vs baseline recovery rate (e.g. 60% vs 45%), never the event rate alone. **Robustness:** 100% retracement (Close back to prev-day Close). **Separate tradable analysis:** forward returns from the specified entry price, computed independently (recovery can happen overnight before a tradable entry). | Raised: (1) no baseline ⇒ a ~60% rate could be pure chance (random-walk estimate 55–65% for a +1% touch within 5 days); (2) High vs Close ambiguity; (3) recovery ≠ tradable return because entry is next-day Open. All three addressed in final definition. Open sub-question: how far a baseline day must rise, since a normal day has no 'loss' (see 3.2a) | 50% measure is the intuitive main definition of 'recover'; Close avoids counting brief intraday touches and matches the close-based event rule; baseline stops a high recovery rate being read as evidence if ordinary days recover as often; 100% tests a stricter definition; forward returns address tradability separately. |
| 3.2a | Baseline recovery target for non-event days (a normal day has no "loss") | A: +1σ (target after a minimum 2σ fall) · B: same % rise as each event · C: same rise in volatility units | **C — volatility-normalised target.** For each event i: k_i = (recovery_level_i / event_close_i − 1) / σ_i. For each normal day j in the same sample period: target_j = close_j × (1 + k_i × σ_j), hit if any Close within N days ≥ target_j. Event i's baseline rate = share of normal days that hit; overall baseline = average across events. σ = same 60-day window as the event rule. | Agreed. Noted A is simplest but biased against the hypothesis (events are usually > 2σ, so their targets are further away); B ignores volatility regime (+2.6% is easy in 2008, hard in 2017) | The event rule is defined in volatility units (2σ), so the recovery comparison should be too; keeps event vs baseline comparable across volatility regimes. |
| 3.3 | Main holding period N | 1 / 3 / 5 / 10 trading days | **N = 5.** Event = day t; window = Closes of t+1 … t+5 (next 5 trading sessions). Same N for recovery window and forward-return horizon. Robustness: N = 1, 3, 10. Window is fixed from the event date — never "wait for the first up day, then start the clock". | Agreed; 5 ≈ one trading week is the closest match to "next few trading days"; pre-committing one main N guards against tuning the horizon | Matches the hypothesis wording. Rejected a "start after first up day" variant: it conditions on post-event price action (a selection/timing rule chosen after seeing the path), which would bias recovery upward. |
